# Domain packs — 포트폴리오와 보고서를 구별하는 법

포트폴리오란 단순 정보 요약이 아니라 **자신이 수행한 작업과 선택의 근거를 의도적으로 편집한 작품집**이다. 분야마다 강조해야 할 증거가 다르다. 모든 분야에 동일한 페이지 카드 템플릿을 주지 않는다.

| Domain | 반드시 묻는 질문 | 핵심 시각증거 | 안티패턴 |
|---|---|---|---|
| architecture | 어떤 공간 문제를 어떻게 해석/발전/결정했나? | 평면, 단면, 입면, 맥락, 매스, 모델, 프로세스 | 렌더만 나열하거나 무관한 문장으로 페이지 채우기 |
| ux-product | 사용자/비즈니스 문제, 연구, 결정과 검증은? | 사용자 흐름, 와이어프레임, 프로토타입, 지표 | 데이터 없이 성과를 꾸며내는 UI 쇼케이스 |
| graphic-branding | 디자인 시스템을 일관되게 다양한 매체에 적용했나? | 타이포, 로고 시스템, 포스터, 인쇄/디지털 응용 | 똑같은 모형(mockup) 반복 |
| photography | 선정한 작품들이 어떤 시리즈/시각언어를 이루나? | 사진 순서/크기/시퀀스/캡션 | 설명문으로 사진을 덮는 일반 보고서형 배치 |

공통: 독자/목적/매체/작품의 역할/포트폴리오 전체 흐름/개별 작업의 출처와 기여도를 기록한다.

### 분야별 별도 파일
- `domains/architecture.md`
- `domains/ux-product.md`
- `domains/graphic-branding.md`
- `domains/photography.md`

**내용 vs 미학 분리:** 도메인 팩은 *무엇이 중요한가*, editorial grammar는 *어떻게 읽히게 할까*를 정의한다.
