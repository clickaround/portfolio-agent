## Not used yet — with a concrete reuse plan (ordered by value to "sources in → good portfolio out")
1. **diagram-design (MIT)** — agent skill that draws 45 editorial diagram types as self-contained HTML+SVG in a brand; has import from Mermaid/draw.io/Excalidraw and a `lint-render.py`. Plan: ship it beside our skills (attributed copy) and route its SVG output into `diagrams/` → our `diagram_row` composition. This is the real "diagram test" (today's SVGs are synthetic placeholders).
2. **pdfcraft (Apache-2.0)** — `crates/preflight`, `audit`, `compare`, `optimize`, `print`: print-readiness checks we only approximate (fonts embedded, page boxes, bleed, ink). Plan: if a signed release binary exists (same family as DesignCraft), run `pdfcraft-cli preflight` as a G5 gate; else BLOCKED (no cargo here).
3. **photocraft-cli / vectorcraft-cli (Apache-2.0)** — headless image adjustments / crop and vector ops; would replace the PIL heuristics in `engine/prepare.py` (sheet trimming, title-block removal) with real, scriptable tools. Same binary caveat.
4. **GDB `src/gdb/metrics` (Apache-2.0)** — typography/layout metrics code. Plan: import selected metric functions into `core/diagnostics.py` (with attribution) to replace our hand-written ones; adds the font-family/size accuracy checks GDB found models fail.
5. **editable-design → `html-to-pptx` + `paper-fig` (Apache-2.0 / MIT)** — converts fixed-canvas HTML to editable PPTX with per-layer text; `paper-fig` makes editable method diagrams as PPTX. Plan: optional exporter for the B0-style HTML path and a second diagram source; lower priority while DesignCraft covers PPTX/IDML.
6. **HarnessRouter (Apache-2.0)** — now that Claude Code and Codex both run `compose`, use UHP as the **benchmark runner** (same fixture across host×model, traces, cost, files) — not as a creation dependency. Plan: spike `runner/` + `protocol/conformance` locally, one job = `compose` on arch_04; keep ADR-0004 unless the matrix proves useful.
7. **pagedjs (MIT) / vivliostyle (AGPL, read-only)** — CSS paged-media engines: the browser/HTML fallback backend (T404). pagedjs is usable; vivliostyle ideas only.
8. **DeepSlides (MIT)** — `pptx_tools` and the design-first pipeline; only if we add a slides-first domain.
9. **deckcraft / figcraft (Apache-2.0)** — deck and design editors of the same family; candidates for presentation-format output and for a Figma-like editing path; binary caveat.
10. **Penpot (MPL), Scribus (GPL), Graphite (Apache, Rust), Fabric.js (MIT)** — editors we will not embed; Scribus GPL = ideas only.

## Honest gaps
- Nothing from the clones was copied as *code* into the package yet; everything is binaries (DesignCraft), re-implementations with attribution, or ideas. That matches the licence gate but under-uses the MIT/Apache repos. Items 1, 4 and 6 above are the first real code-level reuses to do.
- The craft-family CLIs need prebuilt binaries (no Rust toolchain on this machine); DesignCraft had one — check the others' releases before planning on them.
