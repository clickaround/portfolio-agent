# 웹 포트폴리오 자료·대화 저장 설계 초안

상태: **설계 초안, 미구현**. 현재 API는 로컬 디렉터리를 사용하고 인증과 다중 사용자 격리가 없다. 따라서 현재 앱을 인터넷에 공개해 여러 사람의 자료를 받는 것은 이 설계의 완료 조건을 만족하지 않는다.

## 목적과 경계

사람이 사진·도면·PDF·설명문을 프로젝트에 올리고, 에이전트와 대화하면서 편집 가능한 포트폴리오를 만들고, 이전 원본과 편집 이력을 다시 열 수 있어야 한다. 파일 바이트는 객체 저장소에, 사용자·프로젝트·소스 버전·대화·작업 상태는 관계형 DB에 보관한다. 브라우저는 본인에게 권한이 있는 프로젝트만 접근한다.

## 논리 모델

| 엔터티 | 핵심 필드 / 관계 | 역할 |
|---|---|---|
| `users` | `id`, 외부 인증 주체 ID, 생성일 | 로그인 주체. 비밀번호나 LLM 키 원문은 저장하지 않는다. |
| `projects` | `id`, `owner_id`, 제목, 상태, 생성·수정일 | 사용자의 작업 공간. 읽기·쓰기는 소유자 또는 프로젝트 구성원 권한으로 제한한다. |
| `project_members` | `project_id`, `user_id`, 역할, 생성일 | 공동 작업이 필요할 때 쓰는 명시적 권한 관계. 초기 개인용은 소유자만 사용한다. |
| `assets` | `id`, `project_id`, 종류, 표시명, 생성자 | 원본 자료의 논리적 식별자. 파일명 대신 ID로 참조한다. |
| `asset_versions` | `id`, `asset_id`, 버전, 객체 키, SHA-256, 크기, MIME, 상태, 생성일 | 원본과 파생본을 불변 버전으로 추적. 원본을 덮어쓰지 않고 변환 관계를 기록한다. |
| `asset_derivations` | 입력·출력 버전 ID, 변환 종류·설정, 작업 ID | 잘라내기 등 파생 과정과 출처를 추적한다. |
| `conversations` | `id`, `project_id`, 제목, 생성자, 생성·수정일 | 프로젝트별 대화. 다른 프로젝트와 분리한다. |
| `messages` | `id`, `conversation_id`, 역할, 본문, 순서, 생성일 | 사용자·에이전트 메시지. 순서 유일성과 페이지네이션을 보장한다. |
| `message_assets` | `message_id`, `asset_version_id`, 전달 범위 | 어떤 버전의 자료가 해당 메시지에 첨부됐는지 기록한다. |
| `agent_runs` | `id`, `project_id`, `conversation_id`, 상태, 공급자·모델, 입력 버전 및 산출물 참조, 시간 | 비동기 작업의 추적과 실패·재시도. 모델·비용이 확인되지 않으면 `unknown`/`null`이다. |
| `documents` / `document_versions` | 프로젝트 ID, 문서 ID, 버전, native/PDF 객체 키와 해시, 부모 버전, 생성자 | 편집 가능한 파일과 렌더 결과를 같은 버전으로 묶는다. 파생 여부가 확인되지 않으면 비교 참조로만 남긴다. |
| `reviews` | 문서 버전, 확인한 해시, 검토자, 검토 결과, 생성일 | 파일이 바뀌면 이전 검토를 자동 통과로 재사용하지 않는다. |

필수 관계: `users → projects → assets → asset_versions`, `projects → conversations → messages → message_assets`, `projects → documents → document_versions → reviews`. `agent_runs`는 대화·소스 버전·생성 문서 버전에 연결한다. 모든 교차 참조는 같은 프로젝트에 속하는지 서버와 DB 제약에서 검증한다.

## 업로드와 에이전트 흐름

1. 인증된 사용자가 프로젝트에 업로드 요청을 하면 서버가 프로젝트 권한, 크기·형식과 업로드 한도를 확인하고 임시 객체 키를 발급한다.
2. 업로드 완료 후 서버가 실제 바이트, 크기, 해시와 형식을 검증하고 `asset_versions`를 `ready`로 확정한다. 실패하거나 중단된 업로드는 `pending`/`failed`로 남기고 정리한다. 객체 저장과 SQL은 단일 트랜잭션이 아니므로 확정·재시도·정리를 멱등으로 구현한다.
3. 메시지에는 프로젝트 소유의 `ready` 버전 ID만 첨부한다. 사용자가 보낸 메시지와 실제 공급자에 전달한 버전·추출 범위를 기록한다. 이미지나 원문을 읽지 않은 경우 읽었다고 표시하지 않는다.
4. 에이전트가 제안 또는 편집 작업을 만들면 입력 버전과 출력 버전을 연결한다. 편집 결과를 저장할 때 새 문서 버전을 만들고 렌더·출처·사람 검토 상태를 별도로 기록한다.
5. 사용자는 자료·대화·프로젝트를 삭제할 수 있어야 한다. 객체 저장소의 파생본과 보존 기간이 있는 백업까지 포함해 삭제·복구 정책을 제품 운영 전에 명시하고 검증한다.

## 저장소 선택

- **현재 코드에 가까운 후보:** FastAPI와 에이전트 실행 환경은 유지하고, 관계형 DB는 PostgreSQL, 대용량 파일은 S3 호환 객체 저장소를 사용한다. 로컬 개발은 별도 로컬 어댑터로 유지한다. PostgreSQL 공급자와 인증 공급자는 미결정이다.
- **CF가 Cloudflare를 뜻한다면:** R2는 S3 호환 API와 제한된 시간의 업로드·다운로드 URL을 제공하므로 파일 저장소 후보가 된다. [R2 문서](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)
- D1은 Workers 바인딩 중심이다. 현재 별도 FastAPI 서비스에서 D1을 쓰면 접근용 Worker 등 추가 경계가 생기므로, FastAPI 유지와 Workers 중심 재구성 중 배포 구조를 정한 뒤 비교한다. [D1 접근 가이드](https://developers.cloudflare.com/d1/tutorials/build-an-api-to-access-d1/)

## 구현 순서와 완료 조건

1. 인증과 `users/projects/project_members` 모델, 프로젝트 단위 접근 검증.
2. 객체 저장소 어댑터 및 불변 `assets/asset_versions` 업로드·검증·다운로드. 기존 로컬 프로젝트는 별도 이전 도구로 가져오며 원본 경로를 덮어쓰지 않는다.
3. `conversations/messages/message_assets` 영속화와 자료 선택 UI. 현재 대화 패널의 메모리 상태를 대체한다.
4. 지속 가능한 작업 큐와 `agent_runs`, 문서 버전·검토 바인딩 연결. 다중 프로세스에서 작업 상태가 유실되지 않아야 한다.
5. 사용자 A가 사용자 B의 프로젝트·파일·대화를 읽거나 변경하지 못하는 테스트, 중단 업로드·재시도·해시 변경·삭제 후 접근 차단 테스트, 실제 브라우저→API→DB/객체→에이전트 전체 흐름 검증.

미결정: CF가 Cloudflare인지, 로그인/DB 공급자, 배포 위치, 공동 작업 범위, 파일 크기·보존 기간과 모델 공급자별 자료 전송 정책. 실계정 생성·클라우드 배포·마이그레이션은 아직 수행하지 않았다.
