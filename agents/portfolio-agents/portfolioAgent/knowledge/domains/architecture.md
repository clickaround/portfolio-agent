# Architecture — Portfolio Knowledge Pack v0.1 (PROPOSED)

## Primary first-party guidance
- [Georgia Tech School of Architecture Portfolio Guidelines](https://arch.gatech.edu/portfolio-guidelines-graduate-applications): selected projects, intent diagrams, plans, sections, 3D, details; individual contribution and layout attention.
- [UIC School of Architecture Graduate Portfolio Guide](https://arch.uic.edu/sites/arch.uic.edu/files/pdfs/Portfolio%20Guide_2.pdf): design thinking rather than drafting alone; original work, simple layout, white space, vector linework, credits.
- [Harvard GSD application FAQ](https://www.gsd.harvard.edu/offices-and-facilities/admissions-office/apply/navigating-application-faq/): project dates, academic/professional context, collaboration ownership, precise file/page limits, line weights.
- [AUT architecture portfolio](https://www.aut.ac.nz/study/study-options/architecture-and-built-environment/portfolio-guidelines-applying-to-study-architecture): design process evidence important.
- [Penn admissions](https://admissions.upenn.edu/how-to-apply/preparing-your-application/supplementary-materials): AI use may require disclosure.
- [UMass architecture portfolio guidance](https://www.umass.edu/architecture/academics/undergraduate-studies/portfolio-content-and-presentation-guidelines): some submissions prohibit generative AI; don't assume allowed.

## Evidence graph — no invented design facts
For each project record: title, type, place (if public), year, academic/professional, user role, team credit, brief/problem, concept, constraints, alternatives, decision, drawings, physical form, result, limitations; each claim linked to original source ID. If missing, ask for fact or leave unverified; never invent dimension/occupancy/FAR/legal compliance.

## Page grammar (not fixed templates)
- `hero`: one dominant image + project ID; no redundant bullets.
- `site`: location and context analysis / diagrams / constraints; scale and orientation meaningful.
- `concept`: an argument made with 1–3 diagrams, not decoration.
- `process`: legible variation/iteration with clear sequencing and changed constraints.
- `drawing`: plan/section/elevation as evidence, hierarchy, north arrows/labels if relevant; preserve original geometry.
- `sectional`: reveal spatial relationship, not decorative cuts.
- `technical`: details / materials / assemblies only when connected to design claim.
- `realization`: built image + team and contribution, not fabricated outcome.

## Visual editorial rules (heuristics, test with users)
1. One dominant design decision or drawing per spread; visual evidence first.
2. Use white space deliberately; remove paragraphs that duplicate the visuals.
3. Small labels must remain legible at final printed/display size. Check zoom and typography.
4. Plans, sections, elevations and isometrics must maintain geometry, internal labels and relative scale; never re-generate as illustrative art.
5. Repeated 3-column cards and generic KPI boxes are likely **report-style failure**.
6. Alternate visual pacing: a hero spread followed by a drawing/process spread as project demands (not rigid pattern).
7. Use project-specific representation: diagrams, drawing plates, renders and model photos may coexist.
8. Explicit contribution & source credits in team/professional projects.
9. Validate recipient constraints (blind review, page max, size max, AI policy) before export.

## Human reviewer prompts
- Could a portfolio reviewer identify the main design idea within ~10 seconds?
- Is the selection of drawings sufficient to establish spatial thinking, not just software proficiency?
- Is the dominant asset visually justified by the project's argument?
- Does this read like a curated studio portfolio rather than a report/dashboard?
- Do credits, dimensions and claims match evidence?
