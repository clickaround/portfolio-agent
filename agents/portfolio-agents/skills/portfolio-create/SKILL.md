# Portfolio Create

Read `AGENTS.md`, active task card, `../../project/cases/README_V3.md`, selected `portfolioAgent/knowledge/domains/<domain>/`, and `../../project/formats/output-contract.schema.json` before execution. Confirm user purpose, reading audience, ordered projects, print/digital medium, selected dimensions and current asset availability. Asset/provenance must be immutable. Retrieve approved reference case *structures* and write whole-document visual narrative before individual page layouts. Request 3 truly different layout compositions with distinct hero/supporting hierarchy, not three palette swaps. Use only a reproduced chosen backend adapter; otherwise create a reproducible temporary HTML/SVG baseline and clearly label editable limitations. Run independent hard gates, expert aesthetic evaluation when available and a scoped edit test. Export editable project and output with evidence report. **Do not claim fully produced pages unless files exist and render checks ran.**

## Runtime (implemented vertical slice)
Run from the plugin root, identical in Claude Code and Codex:
`python scripts/portfolio.py run <project_dir> <out_dir> [--domain architecture|ux-product|graphic-branding|photography|industrial-design] [--width-mm N --height-mm N --margin-mm N --bleed-mm N --pages N]`
Project dir = `project.md` (title/domain/keywords + `## Section` text) + `images/` + `drawings/*.pdf`. Outputs: `book.pdf` (PDF assets stay vector), `book.pptx` (editable), `scenes/page-XX.json` (canonical editable source), `qa.json` (hard gates). Exit code 1 = a hard gate failed; report it, never call the result finished. Patterns are SYNTHETIC (see `runtime/portfolio_agent/patterns.json`); aesthetic quality is NOT verified by this command.

Style options (all optional, user-controlled): `--no-footer`, `--footer-text "{title}  {page:02d}/{total:02d}"`, `--font-title`, `--font-body` (font file path or installed font file name; unknown font = error, never silently substituted), `--body-pt`, `--title-scale`, `--text-color "#rrggbb"`, or `--style-json file.json`. Ask the user about footer/fonts/size when not stated; do not assume a footer.

## Host-authored pages (B4, legacy: writing coordinates by hand lost to the book-plan path in every blind test - prefer `compose`)
When you (the host) design the pages yourself: `python scripts/portfolio.py manifest <project>` for asset ids/aspects, write `design-plan.json` + `page-NN.json` scenes (../../backend/common/contracts/scene-document.schema.json; graphics `locked: true`, box aspect == asset aspect, nothing outside the margin box, no overlaps), then `python scripts/portfolio.py check-scenes <project> <scenes_dir> <out> --design-plan <plan> [--also designcraft]`. Fix the printed gate issues and repeat (max 5 rounds). The engine never invents layout for host scenes; it only gates, repairs text fit/margins, exports and proves local edits. Architecture and extension rules: `../../backend/common/ARCHITECTURE.md`.

### Book plan (preferred host workflow: you decide, the layout layer draws)
Hosts without a dedicated file-read tool (Codex CLI) read the files named below with read-only shell commands (`Get-Content`, `cat`, `type`); a rule that forbids all shell commands except the engine CLI blocks such hosts (observed 2026-11-05).
Write `book-plan.json` (schema: `../../backend/common/contracts/book-plan.schema.json`) and run `python scripts/portfolio.py compose <project> book-plan.json <out>`.
You decide the editorial things: page sequence and roles (`cover`, `split` = one image + text column, `hero` = one image that fills the page, `pair` = two images, `grid` = 3-6 images, `text`, `closing` = statement + keyword row), which asset goes on which page (every asset at least once, ids from `manifest`), section names, headings, body text (facts from project.md only), one-sentence captions, the closing statement, keywords, `tokens` (paper/ink/accent colour, `display`: serif|sans) and optionally `variant` (0/1 mirrors a page). You never write coordinates: the layout layer places everything on a 12-column grid with the measure, line spacing and hierarchy from `portfolioAgent/knowledge/editorial/layout-craft.md`; the engine then gates, repairs text fit, exports PDF/PPTX (+ `--also designcraft`) and writes `preview/page-NN.png` so you can look and revise the plan. Put the strongest, page-shaped image on the cover and on `hero` pages (aspect near the page), portrait pairs together, a wide panorama on a `split` (it becomes a banner). Credits (role, team, year) belong in `closing.statement`, never as a page heading.

### Finish only through the fresh-review gate (ADR-0009)
`compose`/`run` never overwrite history: each run adds `attempts/NN/`. When gates pass (`gate_pass: true`; `advisory` codes are diagnostics you should still read), run `python scripts/portfolio.py review-context <out>`, hand `attempts/NN/preview/*.png` + `reviewAgent/knowledge/critic-rubric.md` + the printed hashes to a FRESH reviewer (a subagent or a new session that did not write the plan), have it return the review JSON described in `reviewAgent/src/portfolio_agent/engine/review.py` (copy the hashes verbatim, `reviewer_mode: "fresh_subagent"`), then `record-review <out> review.json` and `finalize <out>`. A `revise`/`fail` verdict means a new plan and a new attempt, not a bigger font.

### Editorial devices the layout layer renders for you
- **Captions with a bold lead**: write captions as `Short name. Rest of the sentence.` (lead <= 48 chars) and the lead is set in the heading face on its own line.
- **Index of sheets**: a page `{"role": "grid", "index": true, "assets": [all drawings]}` renders every drawing as a numbered thumbnail (repeats allowed on this page only).
- **Diagrams**: files in `diagrams/` (SVG/PDF/PNG) are role `diagram`; 2-4 on one `grid` page render as an equal-height row with numbered captions.
- **Background and colours**: paper is white by default; the user chooses with `--paper-color`, `--accent-color`, `--text-color`, or `tokens` in the book plan. Never assume a warm paper unless asked.
- **Full-bleed pages** (from real portfolios, `portfolioAgent/knowledge/cases/user_cases_2026-11-05.json`): add `"bleed"` to a page - `"full"` (one photo covers the page to the bleed, label/heading/caption on a solid panel; openers, covers), `"split"` (photo off three edges on 2/3, text column beside it), `"top"` (photo off the top down to 62 %, heading + text below), `"grid"` (2-4 photos tiled to the trim with thin gutters). Only raster photos are cropped to cover (centred); drawings/SVG are never cropped. Running header/footer are dropped on bleed pages. Text may sit on a photo ONLY inside the panel (gate `TEXT_OVER_IMAGE`), so legibility never depends on the photo. Use bleed for 1 in 3-4 pages at most: openers and the strongest photographs; plates and diagrams stay on the white grid.
- **Dark pages**: `"dark": true` swaps paper and ink for that page (night / model photos on black, as in the cases); combine with `bleed`. One or two per book, never for drawings.
- **Process strip**: `{"role": "grid", "strip": true, "assets": [4-10], "captions": [...]}` renders ONE row (two above 6) of equal numbered thumbnails under the heading - construction sequences, iterations, a sheet series.
- **Photo sets (2-6 photographs on one page)**: a `grid` page of 3-6 photos takes the photo-set template that fits their aspects best (`portfolioAgent/knowledge/patterns/photosets.json`: lead-left / lead-top / triptych / quad / mosaic 2+3 / 2x3 ...); name one with `"photoset": "lead-left-3"` (first asset = lead) and, if you accept centred crops, `"crop": "cover"`. See all of them with your own photos: `python scripts/portfolio.py catalogue <project> <out> --photosets [--cover]` -> `photosets_guides.png`. A new arrangement is one JSON entry.
- **Cut-outs**: see `skills/portfolio-cutout/SKILL.md` - name the product / model / object photos whose background adds nothing, run `cutout`, and place them on white with `split` or `hero` (never `bleed`).

### Grid systems and slot compositions (layout variety is data, not code)
Also available: 46 board layouts imported from the user's pptAgent (`pascal-*` ids in `portfolioAgent/knowledge/patterns/compositions-pascal.json`, practice-report boards: drawing + rail, sheet grids 2/4/6/8, hero + panels, stats). A brand or palette comes from a pptAgent `DESIGN.md` / `tokens.json`: `--design-md <file> [--palette neutral-accent|ink-dark|blueprint-mono]`; a cover spine or band: `--band left:#B44A2B:6` (book plan: `band`). Page metrics `WHITESPACE_EXCESS` (> 45 %) and `IMBALANCE` (d > 2.0) are advisory diagnostics ported from pptAgent (AeSlides formulas) and appear per page in `qa.json.page_scores`.
Pick one `grid_system` per book from `portfolioAgent/knowledge/patterns/grid-systems.json` (`swiss-12`, `editorial-8`, `book-6-ninths`, `poster-4`) and, per page, optionally a `composition` id from `portfolioAgent/knowledge/patterns/compositions.json` (17 slot layouts: hero bleeds, two-thirds splits, plates with margin notes, pair rows/stacks, triptych, quad, panorama band, statement pages, covers). Run `python scripts/portfolio.py catalogue <project> <out>` to render your project's own assets under every grid x composition with guides (`catalogue_guides.png`) and choose by eye. To invent a layout, add a JSON entry (slots as fractions of columns/rows; tests check slots never overlap) instead of writing coordinates.

### Grid helper (do not compute box geometry by hand)
`python scripts/portfolio.py grid <project> [--design-plan plan.json] [--columns 12]` prints the column x positions inside the margins and, per asset, aspect-exact `{span, w, h}` boxes. Place a graphic at `grid.x[start_col]` with one of its listed boxes; use the same span for images meant to read as a pair and align their tops and bottoms. Text boxes should use the same column edges.

### Typography tokens (scene schema_version 0.2.0)
Set `"schema_version": "0.2.0"` to add an optional `style` object per element (0.1.0 scenes stay valid):
`font` (installed font FILE name or path - pick the italic/bold file itself, e.g. `georgia`, `georgiai`, `georgiab`, `cambria`, `malgun`, `malgunbd`; unknown fonts fail loudly), `color` (#RRGGBB), `align` (left|center|right), `line_height` (0.9-2.5), and for `kind: "shape"` `fill` (#RRGGBB: tint panels, hairline rules = shape with ~0.3 mm height). The local backend renders all of them (PDF + PPTX); DesignCraft export currently ignores `style` and says so in its notes. Gates measure text with the same style, so a bigger `line_height` really needs a bigger box.
