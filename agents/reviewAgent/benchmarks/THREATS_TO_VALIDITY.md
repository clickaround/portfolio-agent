# Threats to validity

- **Benchmark leakage:** source creator/project, near duplicates and stylistic forks can enter both reference and heldout. Must inspect by creator, content and perceptual near-duplicate; freeze splits.
- **Reference rights:** browse != store != train. Acquired data cannot be reused outside granted scope; deletion/withdrawal invalidates downstream caches.
- **Judge bias:** LLM judge may reward colorfulness/over-decoration and penalize minimal architectural plates. Keep separate human preference and hard gates.
- **Technical confounds:** changing LLM, backend, iteration budget and reference library simultaneously hides causal effect. Fixed-run IDs and controlled factorial contrasts.
- **Small N:** 1 project 3 designs proves smoke only. Any customer preference claim needs multiple disjoint projects/reviewers, uncertainty intervals, ties/invalids.
- **PDF preservation:** correct asset hash != correct rendered output; raster similarity != vector preservation; inspect both.
- **Missing rights:** synthetic prototypes can be technically valid but not demonstrate professional usability.
- **User-context:** job-vs-school-vs-company proposal can yield different valid designs; evaluate with stated goal.
- **Agent memory:** transcript can hallucinate tests; recorded logs/file hashes win over notes.
- **Environment drift:** model aliases and Git HEAD change; pin SHA/version + API/judge parameters.
